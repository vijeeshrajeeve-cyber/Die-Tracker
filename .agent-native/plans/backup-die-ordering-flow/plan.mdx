## What this covers

The Backup Die Requests screen is where a die requirement is captured **before** it becomes a formal die order. The storyboard above walks the eight states a user actually sees, in the order they hit them: raise a request, get past the duplicate guard, chase the design team for drawings, then convert the request into a stamped die order plus a J-file.

Everything on this screen lives in a single component, `src/components/backup/BackupDieRequests.jsx`, mounted from `src/DieOrderingSystem.jsx:2909` when the `backup-requests` tab is active. It receives `backupRequests`, `plants`, `user`, `emailTemplates`, and an `onCompose` callback that opens the shared email composer.

There are two distinct exits from a request, and they are independent of each other. Chasing drawings writes a `Drawing Requested` date. Generating the order produces files and is reachable from the row action at any time — including before any drawing was ever requested.

Status is worth calling out. The dropdown offers `Pending`, `HOLD`, and `Not required`; `Completed` only appears as an option if the record is *already* Completed. So completion is never something a user sets here — it arrives from the ordering side.

## Things I noticed while mapping this

<Callout id="co-admin" tone="risk">

**The order action is not permission-gated.** Edit and Delete are wrapped in `user?.role === 'admin'`, but the green Generate Die Order PDF button is rendered for every user. Any user who can see the page can produce a stamped die order and a J-file.

</Callout>

<Callout id="co-prompt" tone="warning">

**One raw `window.prompt` survives in the save path.** When a die has a profile but no customer and the lookup misses, `handleSave` calls `window.prompt(...)` to collect the customer name, while the rest of the component uses the shared `dialogs` provider. It is the only unstyled, unthemed dialog in the flow.

</Callout>

<Callout id="co-frozen" tone="info">

**Frozen-design prefill is best-effort.** The lookup is wrapped in a bare `catch` that proceeds without prefill, so a lookup failure and a genuine no-match are indistinguishable to the user — the order form simply opens emptier than expected.

</Callout>
